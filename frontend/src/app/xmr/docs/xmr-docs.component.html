xmr.tx.taxi reports public node and chain data. Monero deliberately keeps payment values, recipients, and address histories private, so this explorer marks those limits instead of guessing.

What is xmr.tx.taxi?

A block and pending-transaction explorer for Monero. It adapts the familiar mempool explorer view to data a Monero node can prove publicly.

What is a mempool?

A node-local set of valid transactions observed but not yet included in a block. There is no single global mempool: the site shows the configured daemon’s get_transaction_pool response when last polled.

Why are amounts hidden?

RingCT hides output amounts with commitments, while stealth addresses hide recipients behind one-time outputs. Public data exposes transaction structure, fees, block inclusion, key images, and ring-member references, but cannot derive payment values or recipients.

Transaction proofs and wallet scans are participant checks; they do not turn a public address into a public history.

Why is there no public address history?

A Monero address is not an on-chain account with visible outputs. Wallets use view keys to recognize their own one-time outputs. The explorer does not claim an account balance, UTXO set, or transaction history for an address.

How do Monero fees work?

Public fees are atomic units per byte. The daemon estimates slow, normal, fast, and fastest priority rates; wallets apply a chosen rate to transaction weight and fee quantization. Projected blocks summarize observed pending fee/weight data and do not guarantee inclusion.

What does pending or confirmed mean?

Pending means this daemon currently observes the transaction in its pool. Confirmed means a daemon returned it as included at a block height; confirmations grow as newer blocks arrive. Absence from one node’s pool is not proof a transaction never propagated or will not confirm.

Can I verify a payment?

The transaction page can verify a public tx_proof when monero-wallet-rpc is configured. Recipient scans with a private view key and sender checks with a transaction secret key run in the browser; private key material is not sent to this API. A private view key alone is not a subaddress-proof tool.

How are mining pools identified?

Pool labels are best-effort: public miner-transaction extra markers and, where published, proof-registry evidence. Unattributed blocks remain Unknown; a label never identifies an individual miner.

REST API

Documented routes are read-only and same-origin under https://xmr.tx.taxi/api/v1/. No authentication, wallet, or account API is exposed. Values are atomic units where a route exposes a fee or reward.

curl https://xmr.tx.taxi/api/v1/info

Transaction proof verification POST

/tx/:hash/verify-proof accepts a public tx_proof, address, and optional message. It returns 503 if monero-wallet-rpc is unavailable. Never send a private view key or transaction secret key to this endpoint.

cURL
curl -X POST https://xmr.tx.taxi/api/v1/tx/<tx-hash>/verify-proof \
  -H 'content-type: application/json' \
  -d '{"address":"<address>","signature":"<tx_proof>","message":"invoice-42"}'
Public daemon bridge POST

/monerod/json_rpc and /monerod/:method proxy an allowlisted public daemon subset for browser-local verification. Wallet methods and secret-shaped fields are rejected; this is not a general remote node or wallet service.

cURL
curl -X POST https://xmr.tx.taxi/api/v1/monerod/json_rpc \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":"0","method":"get_info"}'

WebSocket API

Connect to wss://xmr.tx.taxi/api/v1/ws. The server immediately sends a snapshot; {"action":"init"} requests another. Messages use the established mempool protocol shape.

Browser
const socket = new WebSocket('wss://xmr.tx.taxi/api/v1/ws');
socket.onmessage = ({ data }) => console.log(JSON.parse(data));
socket.onopen = () => socket.send(JSON.stringify({ action: 'init' }));
Server messages

Snapshots and updates can contain blocks, block, mempool-blocks, mempoolInfo, fees, bytesPerSecond, transactions, and da. A projected-block subscriber also receives projected-block-transactions. Treat all as observations from the configured daemon, not global finality.

Client messages
MessageBehavior
{"action":"init"}Request the current snapshot.
{"action":"ping"}Receives {"action":"pong"}.
{"track-mempool-block":0}Subscribe to a projected block snapshot by index.
{"track-tx":"<hash>"}Track public confirmation status for one transaction hash.

Address tracking is intentionally not a public Monero stream feature.

Server-Sent Events

Open https://xmr.tx.taxi/api/v1/events as text/event-stream for one-way updates. Proxy buffering is disabled and the stream begins with a snapshot.

Browser
const events = new EventSource('https://xmr.tx.taxi/api/v1/events');
events.addEventListener('block', ({ data }) => console.log(JSON.parse(data)));
Events and reconnection
EventPayload
snapshotCurrent daemon info and observed mempool hashes at connect.
blockA new public block header.
mempool-delta{"added":[…],"removed":[…]} for the observed pool.

A comment heartbeat is sent every 25 seconds. Native EventSource reconnection is suitable for most clients; resync from the snapshot or REST after a disconnect.
